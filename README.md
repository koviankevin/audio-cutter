# 音剪 · Audio Cutter

留下想聽的部分。在瀏覽器內剪輯單一音檔，刪除多個段落、預聽結果，再匯出 MP3 或 WAV。

## 使用

### 保存與繼續剪輯

剪輯進度會自動保存在這個瀏覽器。看到「已自動保存」後，重新開啟網站可展開「最近的剪輯備份」並按「繼續剪輯」，選回原始音檔即可還原。程式會分塊核對整份檔案內容，同名但內容不同的音檔不會套用舊剪輯；原檔改名但內容相同仍可還原。

「儲存專案檔」會下載 `.yin-jian.json`，保留剪輯區間、待刪清單、復原／重做、檔名、格式及波形視圖。「開啟專案檔」可在另一個瀏覽器設定檔還原。專案檔與自動備份都不包含音檔，請一併保留原檔。示範音訊的專案可直接還原。

每次還原建立獨立工作備份，保留舊版，避免分頁互相覆寫。列表可展開更多備份並逐份移除。瀏覽器資料可能被清除；重要剪輯請下載專案檔備份。儲存被禁止或失敗時，仍可繼續編輯並下載專案檔。換檔失敗或取消時會保留原本的剪輯。

編輯器的「最近備份」會移至工作區下方，避免自動保存時推動波形。原檔識別在背景 Worker 分塊計算，可取消；核對通過才會套用專案。

匯出前會檢查本機暫存能力與估計可用容量；容量不足時保留目前剪輯，釋放裝置空間或縮短範圍後可重試。容量估計並不保證後續寫入成功，實際配額錯誤仍會被處理。

頁面上方可切換「標準／大字／特大字」，分別為原字級的 100%／112.5%／125%，包含波形時間標示。設定僅以 `localStorage` 保存在目前瀏覽器，下次開啟自動套用；同一網站的其他分頁也會同步。若瀏覽器禁止儲存，仍可切換，並提示設定僅適用本次開啟。字級切換不影響音檔、剪輯紀錄或匯出結果。

1. 拖放或選擇 MP3、WAV，也可先按「示範音檔」。
2. 在波形上拖曳選段、拖動選段邊界，或輸入起點與終點。時間格式為 `01:23.456`，也接受秒數，例如 `83.456`。
3. 「刪除選段」剪去選取部分；「只保留選段」留下目前仍存在且位於選段內的音訊。可以連續操作，刪除過的聲音不會因再次選段而復活。
4. 預聽剪輯結果，或播放單一片段。剪輯按原始順序接合。
5. 選擇 MP3 或 WAV、修改檔名並匯出。完成後可用「預聽匯出音檔」播放／暫停並拖曳進度列，確認接點和音質，查看總耗時、平均處理速度與檔案大小後再按「下載音檔」；可重複預聽與下載。

### 一次刪除多段

接點處理預設「原音接合」。可選 5／10 毫秒的短淡化，將實際刪除接點兩側分別淡出與淡入；不重疊片段、不改變總長度。過短片段會縮短淡化範圍。預聽剪輯結果、接點預聽與匯出共用相同處理；播放單一原始片段或選取範圍保留原音。內容接合是否自然，仍需預聽確認。

1. 拖曳波形或輸入起訖時間後，按「加入待刪清單」。再選下一段並加入；電腦也可按住 **Shift 拖曳**，每次拖曳都會加入一段。
2. 待刪段落會以橘色標在波形上，清單會顯示時間、總刪除長度與刪除後長度。重疊或相連範圍會自動合併；可逐段移除或清空清單。
   每個橘色段落左右都有把手，可以直接在波形上拖曳調整起點與終點，清單與預計匯出長度會即時更新。放開後才合併重疊範圍；起點不會越過終點。按 Esc 或觸控中斷會取消這次拖曳；縮放後也能調整可見的把手。
   直接拖曳橘色段落的中間，可整段平移並保持長度不變，游標會顯示抓取手勢；左右把手仍用於調整長度。平移遇到音檔邊界、相鄰待刪段落或已刪除區域會停止，避免合併或縮短段落。縮放後也可拖曳可見的中間區域，按 Esc 或觸控中斷會還原本次移動。按住 Shift 拖曳仍是加入新的待刪段落。
3. 按「預聽刪除後」先確認接合結果，再按「一次刪除清單」。所有段落會在同一次剪輯內刪除；按一次「復原」會還原原音訊及待刪清單，方便再調整。清單仍會套用於預聽與預計匯出長度，清空清單即可聽見完整原音訊。
4. 也可選好 MP3／WAV 後，直接按右側「刪除清單並匯出」，一步完成刪除與合併匯出，查看結果後再按「下載音檔」。

加入清單時還不會刪除音訊；右側會顯示預計匯出長度，主播放鍵與「預聽剪輯結果」也會先跳過待刪段落。時間始終以原始音檔為準。切換檔案或關閉頁面前，待刪清單也會視為尚未完成的修改。

快捷鍵：空白鍵播放／暫停、Delete 刪除選段、Ctrl/Cmd+Z 復原、Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做。輸入欄位內保留原本的文字編輯快捷鍵。在波形上未選取待刪段落時，左右方向鍵移動播放位置 0.1 秒，搭配 Shift 移動 1 秒。

鍵盤微調待刪段落：點選清單中的時間或橘色段落，然後選擇「整段移動」「起點」或「終點」，再按左右方向鍵。每次調整 **10 毫秒**，按住 **Shift** 改為 **100 毫秒**；點選波形左右把手也會自動切換為該起訖點模式。整段移動保持長度，且不能越過音檔、相鄰段落或已刪除區域；起訖點不會交叉。長按方向鍵會連續調整，放開才完成並合併重疊段落，整次長按可一步復原／重做。按 Esc 取消本次長按，切換焦點則完成調整。鍵盤調整與縮放倍率無關。

不切回滑鼠：按 **↑／↓** 循環切換上一個／下一個待刪段落，按 **1／2／3** 切換「整段移動／起點／終點」，再直接用 ←／→ 微調。未選取段落時，↓ 選第一段、↑ 選最後一段；直接按模式鍵會選第一段。切換段落會保留目前模式，並將鍵盤焦點放回波形；縮放時會自動顯示調整目標。切換段落或模式不會增加復原紀錄，也不會清除重做；長按微調期間切換，會先完成這次調整，再切換。這些快捷鍵在時間、檔名等輸入欄位、中文組字及更換音檔確認視窗內停用。

快速確認接點：選取待刪段落後按 **P**（或「預聽接點」），將刪除前最後 **1.5 秒** 與刪除後最先 **1.5 秒** 的保留音訊直接接起來播放，自動停止；重按 P 從頭重聽，**Esc** 停止。上下文取自套用所有實際剪輯與待刪清單後的結果，會跳過其他待刪範圍，與匯出順序一致，依接點處理設定套用短淡化（預設關閉）。前後音訊不足時縮短該側；位於結果開頭或結尾時只播放可用的一側，全部刪除時無法預聽。切換段落、模式或微調會停止目前的接點預聽，方便調整後再按 P。長按微調途中按 P 會先完成該次編輯；單純預聽不修改段落、模式或復原／重做紀錄。輸入欄位內的 P 仍為文字輸入。

邊聽邊調：按 **L**（或「循環預聽」）連續循環目前接點，前後各最多 1.5 秒；再按 L 或 **Esc** 停止。使用 **1／2／3** 切換整段／起點／終點，再用 ←／→（Shift 加大步幅）微調。調整時暫停聲音，放開方向鍵或把手後，立即以新位置從頭循環；長按仍只算一次編輯。↑／↓ 切換段落、切換模式及復原／重做後，也會繼續循環目前選取的接點。Esc 在調整中會取消這次調整並停止循環；L 可單獨停止循環。P 會改為單次預聽。一般播放、另選範圍、清空／套用待刪清單、更換音檔或離開頁面均會停止循環；沒有可預聽的接點時也會停止。循環只複製最長 3 秒的保留音訊到短緩衝區，以 Web Audio 原生循環播放，不會因長時間預聽持續累積音訊節點。

待刪段落的平移、左右把手調整、加入、移除、清空及實際剪輯共用同一條復原紀錄。一次完整拖曳只算一步，按 Ctrl+Z 會恢復整次調整前的位置、選取範圍與播放位置；Ctrl+Shift+Z 或 Ctrl+Y 重做。重疊範圍合併也可一次復原。取消拖曳、點擊但未移動、播放及縮放不會增加紀錄；復原後進行新的編輯會清除原有的重做分支。更換音檔會清空紀錄。

## 格式、隱私與限制

- 輸入：MP3、WAV，最長 30 分鐘、最大 400 MiB、單聲道或雙聲道。其他容器、特殊 WAV 編碼或損毀檔案可能無法解碼。
- 以 44.1 kHz 解碼並處理，保留原始單／雙聲道。輸出為 MP3 192 kbps 或 WAV 16-bit PCM。MP3 會重新編碼，有少量編碼延遲；WAV 不會恢復有損來源已失去的細節。
- 剪輯保留原始樣本索引，播放及匯出使用同一份片段資料。復原記錄最多 100 個狀態，還原原檔也可以復原。
- 音檔不會傳送到網路；無分析追蹤、登入、雲端儲存或第三方字型。網站與編碼器初次載入仍需網路。
- 剪輯設定與復原紀錄會備份至本機 IndexedDB；音檔內容仍不持久保存。尚未匯出的修改會觸發瀏覽器提醒；重新開啟時需選回原檔，已匯出的預聽與下載來源需要重新產生。
- 取消匯出會立即終止匯出 Worker 並移除未完成的輸出暫存；取消分段載入也會終止解碼 Worker，並清除已寫入的音訊暫存。短 WAV 使用瀏覽器原生解碼，取消後會忽略結果，解碼可能短暫繼續。
- 主要支援桌面版 Chrome 與 Edge。手機可基本操作；MP3 解碼及所有匯出均需要可用的瀏覽器本機儲存空間。暫存不足或儲存功能被停用時會顯示錯誤，不會退回完整長檔解碼或累積完整輸出於 RAM。
- 第一版不包含多檔拼接、多軌、片段重排、降噪或語音辨識。

### 長音檔的分段處理

MP3 一律在背景分段解碼，避免可變位元率檔案的估計長度偏小，誤走完整解碼。WAV 大於 4 MiB、超過 60 秒或無法預先取得長度時，也交由背景 Worker 處理；其餘短 WAV 使用瀏覽器原生解碼。

- **WAV**：分塊讀取原始檔案建立波形，播放／匯出時才讀取所需範圍，無須暫存完整 PCM。支援 RIFF／RF64 的 PCM 8／16／24／32-bit、IEEE float 32／64-bit，以及對應的 WAVE_FORMAT_EXTENSIBLE；其他 WAV 編碼需先轉檔。
- **MP3**：固定版本 mpg123-decoder 在 Worker 中以 16 KiB 壓縮區塊連續解碼，保留解碼器狀態。44.1 kHz Float32 PCM 分塊寫入瀏覽器私有檔案系統（OPFS），不把整份 PCM 留在 RAM。正常換檔、取消載入和釋放音訊時刪除暫存；離開頁面會嘗試清除，意外關閉留下的暫存會在下次分段載入時清理。跨分頁的 Web Lock 可避免刪掉另一分頁正在使用的暫存。
- 其他取樣率使用帶低通濾波的重採樣；區塊共用原始時間座標與相鄰樣本，避免分塊邊界重複／漏掉樣本。剪輯區間統一使用 44.1 kHz 樣本索引。
- 預聽按兩秒一塊讀取，只排程前方約四至六秒；播完即釋放節點。接點循環仍只保留最多三秒。匯出每次讀取最多 73,728 個樣本，與預聽使用同一個音訊來源及片段清單。

音訊暫存不會上傳，剪輯設定則另外保存在本機 IndexedDB。30 分鐘立體聲 MP3 解碼最多需約 606 MiB 的本機暫存空間；WAV 分段讀取不需要這份解碼暫存。匯出另需磁碟空間，約為完成檔案的大小（30 分鐘立體聲 WAV 約 303 MiB，MP3 約 41 MiB）。這是磁碟用量，並非完整檔案留在 RAM。OPFS 需 HTTPS 或 localhost，因此請透過網站或本機伺服器開啟。

### 匯出時的記憶體控制

編碼 Worker 保留一份 256 KiB 寫出緩衝，MP3 封包及 WAV PCM 區塊編碼後即寫入 OPFS；每次寫入完成才回覆主頁，避免資料排隊。完成後傳回磁碟支援的 `File` 供直接下載，不再累積整份區塊陣列或組裝完整 `Blob`。主頁只在整數進度改變時更新文字；剪輯、預聽與取消仍可操作。

MP3 預設使用 **wasm-media-encoders 0.7.0／原生 LAME WebAssembly**，在同一個背景 Worker 連續編碼，保留 192 kbps CBR、44.1 kHz 及單／雙聲道。每個音訊區塊直接以 Float32 編碼，避免先轉成 Int16 及大量小呼叫；不降低位元率或取樣率來換取速度。編碼器與 WASM 皆隨站提供，不從 CDN 載入。若 WebAssembly 無法使用或資源載入失敗，則自動回退至固定版本 lamejs 1.2.1。WASM 使用約 **16 MiB 固定線性記憶體**，另有小型區塊與檔案緩衝；不隨音檔長度保留整份 PCM 或輸出。

匯出面板會同時顯示已用時間、目前速度與預估剩餘時間，MP3／WAV 皆適用。已用時間從開始匯出起計算，包含準備與最後寫入，超過一小時改用 `時:分:秒`。速度以即時倍速顯示，例如 `3.0×` 代表每秒處理約 3 秒音訊。

取得約一秒的實際進度前，速度顯示「計算中…」、剩餘時間顯示「正在估算剩餘時間…」。速率採時間加權平滑，包含讀取、編碼、磁碟寫入與區塊往返的實際耗時，約每半秒更新；等待新進度時速度逐漸降低，剩餘時間可上修。最後寫入期間繼續計時，速度顯示 `—`，並改顯示「最後寫入中…」，不提早顯示零秒；取消、失敗、換檔或下一次匯出會清除／重新計算。速度與剩餘時間皆為估計值，會隨裝置負載及磁碟速度變動。

完成後停止計時並保留「本次匯出結果」與實際檔名。總耗時包含準備、讀取、編碼與最後寫入，以十分之一秒顯示；平均速度為本次保留音訊的長度除以完整耗時，與匯出途中的平滑即時速度不同。檔案大小直接取完成檔案的實際位元組數，以 B／KiB／MiB 顯示，滑鼠移到大小上可看精確位元組數，無須再讀入整份檔案。完成後不自動下載，可先查看摘要，再按「下載音檔」；下載後摘要仍保留。開始新匯出、修改剪輯或換檔時，會一併清除舊結果與下載連結，避免誤認為新版本；取消或失敗不會留下成功摘要。

每次匯出固定使用啟動時的片段及淡化設定。匯出期間可繼續剪輯；若完成時已有後續修改，結果會標示「尚未套用」並提醒再次匯出，避免把先前的成品當成目前版本。

「預聽匯出音檔」使用瀏覽器原生音訊播放器，直接播放與下載連結相同的完成檔案，因此 MP3 預聽也包含這次編碼後的音質與延遲。只預載中繼資料，不自動播放，也不另外將整份產出解碼成 Web Audio PCM；播放與跳轉由瀏覽器管理，音訊仍留在裝置內。開始預聽會暫停編輯器播放；回到編輯器播放則暫停產出預聽。播放器取得焦點時保留原生鍵盤控制，不觸發剪輯快捷鍵。開始新匯出、修改剪輯、換檔或離開頁面時會停止預聽，清除舊結果時也移除播放器來源並釋放物件網址。預聽失敗會顯示提示，摘要與下載仍可使用。

匯出後，播放位置滑桿上方會標示剪輯接點。先設定「接點前／接點後」的秒數（預設各 **1 秒**，每側可填 **0–30 秒**及小數，不能同時為 0），再點標記或按「上一個接點／下一個接點」預聽；超出檔案頭尾的部分會縮短。單次預聽到設定終點即暫停，按原生播放可重聽同一範圍。選取的接點會以不同顏色標示，並顯示編號與毫秒時間；連按下一個會依序切換，不必等播放越過接點。

選好接點後按「循環目前接點」即可反覆播放設定範圍，按「停止循環」停止。循環時切換接點會繼續循環新的接點；修改前後秒數會從新範圍起點重聽，暫停時修改則維持暫停。原生暫停／播放可暫停與恢復循環；手動拖曳滑桿或原生播放器跳轉會退出範圍預聽與循環，導覽改依目前播放位置尋找前後接點。回到編輯器播放、換檔、重新匯出、修改剪輯、播放錯誤或離開頁面時均停止循環並清除計時器；秒數設定只保留於目前頁面。沒有接點或輸入無效秒數時，接點預聽按鈕停用並提供提示。

範圍預聽仍播放同一份完成檔案，僅以原生播放器跳轉與單一計時器控制，不另外建立完整 PCM 或改寫下載檔。循環回跳由瀏覽器處理，可能有短暫停頓；回跳邊界不是音檔中的剪輯接點。

匯出播放器的快捷鍵：**`[` 上一個接點、`]` 下一個接點、`L` 循環開／關**。先點播放器區域，或從「匯出音檔」按 Tab 聚焦播放器；原生音訊控制、接點按鈕及播放位置滑桿取得焦點時也可使用。秒數等輸入欄位、中文組字及 Ctrl／Command／Alt／Shift 組合鍵不觸發；長按只執行一次。快捷鍵與按鈕共用相同的停用條件，沒有接點、尚未選好循環接點、輸入無效秒數或媒體錯誤時不會誤播放。離開匯出播放器後，波形編輯器原有的快捷鍵維持原樣。

接點來自本次匯出時固定的保留樣本區間，依合併後時間計算；只剪頭尾或連續區間不產生假接點。標記採剪輯時間，MP3 仍可能帶有編碼延遲，預聽播放的是實際完成檔。標記在完成匯出時建立，播放時僅更新選取狀態與導覽，不重新解碼音訊或重建全部標記；舊下載失效時一併清除接點。

下載連結存在時，以檔案鎖保護完成的暫存，可再次下載。編輯、換檔或開始新匯出會撤銷舊連結、釋放其 Worker；為避免中斷已開始的瀏覽器下載，完成檔保留 **10 分鐘**的磁碟緩衝時間後清除。頁面已關閉時，過期檔與未完成的殘留檔會在下次匯出時清理；另一分頁仍使用的檔案會保留。取消／失敗的輸出立即清理，不走這段緩衝時間。

瀏覽器的原生下載、磁碟快取與編碼器本身仍有資源成本；此設計消除應用程式隨輸出長度累積的完整位元組陣列，並非整個瀏覽器完全不使用記憶體。

## 本機啟動

安裝 Node.js 22 或以上，於專案資料夾執行：

```sh
node scripts/serve.mjs
```

開啟 `http://127.0.0.1:4173/`。網站不需安裝任何套件或執行建置；請使用 HTTP 伺服器，直接雙擊 HTML 會受到模組與 Worker 安全限制。

## 測試

依變更選測。`test:export-preview` 是 CI 的整合入口，包含成品預聽、專案保存與商品操作；本機可單獨使用 `npm run test:projects` 或 `npm run test:product`，避免重複執行相同案例。

```sh
npm ci
npm test
npx playwright install --with-deps chromium
export BROWSER_CHANNEL=chromium
npm run test:browser
npm run test:streaming
npm run test:export-memory
npm run test:export-lifecycle
npm run test:mp3-export
npm run test:mp3-speed
npm run test:export-preview
npm run test:font-size
```

瀏覽器測試使用自己產生的音調資料，涵蓋多段剪輯、MP3/WAV 實際下載與解碼、左右聲道、播放與取消、錯誤檔案、鍵盤、子路徑及沒有音訊網路傳輸。CI 使用鎖定版本 Playwright 安裝的 Chromium，以上指令以 `BROWSER_CHANNEL=chromium` 選取它。測試腳本原本的預設值為已安裝的 Chrome；需要測試已安裝的 Chrome／Edge 時可指定 `BROWSER_CHANNEL=chrome` 或 `BROWSER_CHANNEL=msedge`；`LONG_AUDIO=1` 另外測試 29 分鐘單聲道錄音。

`tests/streaming.mjs` 另驗證 90 秒 WAV／MP3 的實際分段讀取、48 kHz 重採樣、跨段預聽、逐樣本 WAV 匯出、單／雙聲道 MP3 再匯出、取消與換檔暫存清理、其他分頁的暫存鎖，以及 Worker 記憶體。`LONG_AUDIO=1` 額外驗證約 28.5 分鐘立體聲 MP3；首次產生測試 MP3 較久，後續會重用合成測試檔。輸出僅存於 `test-results/`。

`tests/export-memory.mjs` 以真正編碼 Worker 測量匯出約 85% 時、GC 後仍保留的緩衝用量。預設 4 分鐘 WAV；設定 `EXPORT_SECONDS=1740 EXPORT_COMPLETE=1` 可測 29 分鐘完整匯出、完成階段記憶體、再次下載及撤銷連結後已開始的下載仍可完成。`EXPORT_FORMAT=mp3` 改測 MP3；`PERF_LABEL` 設定報告名稱。`tests/export-lifecycle.mjs` 另驗證取消、實際寫入時的配額錯誤、跨分頁鎖、完成檔緩衝時間到期及殘留暫存清理。

`tests/mp3-export.mjs` 以 90 秒雙聲道音調驗證 WASM 路徑、192 kbps／44.1 kHz 輸出、左右聲道、已用時間／倍速／剩餘時間的預熱與更新、準備與最後寫入期間持續計時，以及取消／失敗／換檔／完成後的數值與計時器清理，並檢查手機版面與 JavaScript 相容回退。`tests/mp3-speed.mjs` 量測真正 Worker 匯出不同音調的立體聲 MP3，預設 60 秒；可用 `MP3_SECONDS` 調整測試長度，`PERF_LABEL` 設定報告名稱，`MP3_MAX_MS` 設定此電腦的速度檢查門檻。速度受環境影響，CI 不強制使用固定時間門檻。

測試會記錄網路請求；若主機防毒軟體注入自身的監控腳本，其已知網域請求會另列於 `environment-requests.json`，不視為應用程式請求。測試不會停用或修改防毒設定。

`tests/export-preview.mjs` 以不同音調與兩個刪除接點，驗證實際 MP3／WAV 成品的原生播放、接點標記與前後導覽、完整寬度滑桿跳轉、括號／L 快捷鍵與焦點／輸入／組字保護、原生鍵盤操作、與編輯器互斥播放、結束與重播，以及下載使用相同來源。另檢查預聽錯誤仍可下載、修改／重新匯出／換檔時釋放舊來源、手機版面，並確認預聽不呼叫完整 Web Audio 解碼或傳送音訊。

設定 `SITE_URL=https://koviankevin.github.io/audio-cutter/` 可對已部署網站執行相同的驗收流程。

### 效能檢查

執行 `node tests/performance.mjs` 可量測播放、120 個待刪段落、連續 40 次方向鍵微調，以及波形快取在縮放／捲動時是否正確更新。可用 `BROWSER_CHANNEL=chrome` 或 `msedge` 選擇瀏覽器；`PERF_LABEL=after` 決定報告檔名。報告寫入忽略於 Git 的 `test-results/performance-*/`。

`LONG_AUDIO=1` 另建立 29 分鐘立體聲靜音 WAV，驗證載入、接點循環、MP3 匯出取消、兩分鐘片段的 WAV 匯出及換檔。`PROFILE_IMPORT=1` 會額外儲存載入時的 CPU profile。記憶體數據採 Chrome DevTools 的 backing storage；換檔後強制 GC，以確認舊音訊緩衝區沒有持續留存，並非完整程序的記憶體用量。

2026-10-19 桌面 Chrome、1440×1080 的同機檢查，優化前為 `aa24067`；時間會隨電腦、瀏覽器與背景負載變動：

| 測試 | 優化前 | 優化後 |
| --- | ---: | ---: |
| 播放 1.6 秒的繪圖函式累計耗時 | 約 79 ms | 約 8–10 ms |
| 120 段、同步連續 40 次微調 | 約 1,117 ms | 約 93–114 ms |
| 上述微調新增／移除的清單 DOM 節點 | 9,840 | 18 |
| 一次計算 2,000 個刪除區間（20 次平均） | 約 122 ms | 約 1.1 ms |

波形與標記變動時才重建靜態圖層；播放僅更新播放游標。不變的文字及按鈕不再每幀重寫，清單重用既有列，刪除區間則以排序後的單次掃描處理。效能測試會防止靜態波形每幀重畫與整份清單重建再次出現。

同機的 29 分鐘立體聲 WAV 分段載入約 1.4 秒，先前完整解碼約 3.3–3.6 秒；主頁 backing storage 約由 586 MiB 降至 6.7 MiB（含先前示範音訊，非整個瀏覽器程序用量）。載入未見超過 50 ms 的主執行緒工作，先前有約 0.33 秒停頓。兩分鐘 WAV 匯出約 1.3 秒，匯出取消約 41 ms。

Edge 的約 28.5 分鐘立體聲 MP3 分段解碼約 13.6 秒，約 576 MiB PCM 寫在 OPFS；載入完成並 GC 後，主頁 backing storage 約 0.46 MiB、解碼 Worker 約 0.07 MiB。解碼途中仍有有界的 WASM／區塊／波形緩衝成本，這些完成後的數據並非峰值，也不包含瀏覽器的磁碟快取與整體程序用量。各數字僅代表本次合成音檔測試，會隨裝置、磁碟及背景負載改變。

匯出改採檔案寫出後，同機 Chrome 的合成立體聲測試如下。數值為匯出約 85% 時強制 GC 後，編碼 Worker 的 backing storage，並非整個程序或瞬間峰值：

| 匯出測試 | 原區塊陣列累積方式 | 分塊寫入 OPFS |
| --- | ---: | ---: |
| 4 分鐘 WAV | 約 34.6 MiB | 約 0.26 MiB |
| 29 分鐘 WAV | 約 248.9 MiB | 約 0.26 MiB |
| 29 分鐘 MP3 | — | 約 0.84 MiB |

29 分鐘完整 WAV 約 293 MiB、MP3 約 39.8 MiB 均成功寫出、下載與再次下載；撤銷舊連結後，已開始的下載仍能完成。完成階段的主頁 backing storage 約 0.28 MiB，WAV Worker 約 0.01 MiB、MP3 Worker 約 0.16 MiB。該輪匯出主頁測試沒有超過 50 ms 的工作，20 ms 計時器持續執行。磁碟速度仍會影響完成時間；測試不保證所有裝置的延遲相同。

上述 MP3 緩衝數據為原 JavaScript 編碼器。換用 WASM 後，60 秒非靜音立體聲測試約由 3.7 秒降至 1.5 秒；29 分鐘立體聲合成靜音依序對照測試約由 45.1 秒降至 14.0 秒，約快 3.2 倍。測試包含真正編碼 Worker 及分塊寫出；實際錄音、檔案讀取、初次資源載入與背景負載會影響速度。WASM 的 16 MiB 線性記憶體需另外計入，不能將 DevTools 的 backing storage 數字視為全部原生編碼記憶體。

## GitHub Pages

網站：[音剪](https://koviankevin.github.io/audio-cutter/)。公開儲存庫：[koviankevin/audio-cutter](https://github.com/koviankevin/audio-cutter)。

在 GitHub 儲存庫 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。

PR 與 `main` 更新都會執行 `.github/workflows/pages.yml`，分別顯示兩個驗收工作：

| 狀態 | 驗證內容 | 是否阻擋部署 |
| --- | --- | --- |
| Core tests | 原有 `tests/core.test.mjs` 入口（包含其匯入的串流、儲存與進度測試） | 是 |
| Chromium export acceptance | 原有 MP3／WASM、JavaScript 備援、取消後重新匯出、OPFS 生命週期、匯出摘要／手動下載、成品預聽／接點／快捷鍵與串流瀏覽器測試 | 是 |
| Long audio export measurements | 另行手動執行的 60 秒音調編碼、29 分鐘 WAV／MP3 完整匯出及保留記憶體量測 | 否；不等同上述短音檔驗收 |

瀏覽器工作在 Ubuntu 安裝鎖定的 npm 依賴與 Chromium／Linux 系統套件，先打包，再以 `PUBLIC_ROOT=dist` 對 `/audio-cutter/` 子路徑執行真實瀏覽器測試；WASM、JavaScript 編碼器與解碼器都取自打包內的 `vendor/`，不依賴外部 CDN。MP3 測試會明確斷言使用 WASM，另強制停用 WASM 驗證 JavaScript 備援。OPFS 測試若無法存取儲存空間會失敗，不會當成「已清理」。

`deploy` 明確依賴兩個驗收工作成功，僅在 `main` 的 push 或手動執行時部署同次已測試的 Pages artifact。PR 只驗收、不部署；取消、失敗或跳過驗收均不會部署。不同 PR 使用不同 concurrency 群組，不會取消正式分支的驗收。

瀏覽器 JSON／截圖證據以 `browser-export-<commit>` artifact 保留 14 天。需要長音檔數據時，在 Actions 選擇 **Long audio export measurements → Run workflow**，其 JSON 以 `export-measurements-<commit>` 保留 30 天；包含提交、瀏覽器／Node／作業系統／CPU、音檔類型及測試長度，沒有音訊檔。這個流程沿用 `tests/mp3-speed.mjs` 與 `tests/export-memory.mjs`，保留檔案輸出與有界記憶體的正確性斷言，不設定 `MP3_MAX_MS`，不以固定毫秒數判定效能退步。

長音檔記憶體報告為約 85% 與完成時 GC 後的保留量，另記錄 WASM 線性記憶體；不代表峰值、瀏覽器磁碟快取或整個程序用量。合成音調／靜音結果只描述該次 runner，不能保證所有裝置或真實音檔的速度。只有實際執行該工作後，才算有該提交的長音檔驗證結果。

部署只包含網站資源，不包含測試輸出或音檔。所有資源及 Worker 使用相對網址，可部署於 `/audio-cutter/` 子路徑。
